Overview & Architecture

Qalam is engineered from first principles for the Djazair Programming Language. It completely decouples lexical analysis, parsing, filesystem resolution, caching, and tree traversal into clean, single-responsibility modules under core/, coordinated through a lightweight public orchestrator in init.dz.

Module File Path Core Responsibility
Public Entry Point init.dz Exports view class, renderString helper, and escapeHtml security utilities.
Lexer / Tokenizer core/lexer.dz Linear token scanner supporting comments {#...#}, whitespace trimming {{- -}}, tags, and raw blocks.
AST Parser core/parser.dz Transforms flat token stream into structured hierarchical AST node trees with block matching.
Loader & Cache core/loader.dz Path traversal security containment, filesystem reading, and in-memory compiled AST caching.
Evaluator Engine core/evaluator.dz Recursively evaluates AST nodes against data context; handles operators, direct callables, and loops.
Filter Registry core/filters.dz Maintains built-in standard filters and dynamically registered user callbacks.
HTML Escaper core/escaper.dz High-throughput entity encoding preventing Cross-Site Scripting (XSS).
Type Constants core/constants.dz Semantic token and node type constants eliminating magic strings.

Installation & Setup

Install Qalam into your Djazair project using the official package manager (dpm) or include it directly as an extension.

terminal 
# Install via official Djazair Package Manager
dpm install qalam

# Or clone directly into your project extensions folder
git clone https://github.com/djazair-language/djazair-extensions.git

In your Djazair scripts, import the engine with standard module syntax:

djazair 
use qalam

# You now have immediate access to qalam.view, qalam.renderString, and qalam.escapeHtml

Quick Start Guide

Render dynamic templates using either the fast in-memory helper or the full file-based orchestrator.

Ideal for email notifications, dynamic code generation, API payload rendering, or command-line tools:

djazair 
use qalam

let emailTemplate = `
<h1>Welcome, {{ user.name | capitalize }}!</h1>
<p>Your temporary access token is: <code>{{ token }}</code></p>
<p>Expires in {{ ttl }} minutes.</p>
`

let output = qalam.renderString(emailTemplate, {
    "user": {"name": "riad harizi"},
    "token": "DZ-8941",
    "ttl": 30
})

print(output)

Ideal for multi-page web applications, enterprise dashboards, and layout inheritance:

djazair 
use qalam

# Initialize view orchestrator with templates directory and caching enabled
let v = new qalam.view({
    "views": "views",
    "cache": True
})

# Reads views/dashboard.html, resolves layout inheritance, and renders
let html = v.render("dashboard", {
    "siteTitle": "Algerian Trading Portal",
    "user": {"name": "Riad", "role": "admin"},
    "trades": [
        {"symbol": "DZ-ENERGY", "value": 1450.50},
        {"symbol": "ALG-TECH", "value": 820.75}
    ]
})

print(html)

Variables & Auto-Escaping

Double braces {{ ... }} evaluate expressions against the runtime data context. All variable outputs are automatically HTML-escaped by default to prevent Cross-Site Scripting (XSS).

template.html 
<!-- Auto-sanitized against script injection -->
<h1>User: {{ user.name }}</h1>

<!-- Deep dot-path navigation -->
<p>Location: {{ user.profile.address.city }}</p>

<!-- Array index resolution -->
<p>Primary Phone: {{ user.phones[0] }}</p>
XSS Protection Table: Special characters are encoded into safe entities: & → &amp;, < → &lt;, > → &gt;, " → &quot;, ' → &#039;.

Raw HTML Output (Unescaped)

When rendering trusted HTML markup (such as pre-sanitized Rich Text Editor contents or generated badges), wrap expressions in triple braces: {{{ ... }}}.

template.html 
<div class="article-body">
  <!-- Trusted HTML passes through verbatim without escaping -->
  {{{ article.sanitizedHtmlContent }}}
</div>
Security Warning: Never use triple braces {{{ ... }}} with unsanitized user-submitted data. Doing so bypasses Qalam's automatic XSS shield.

Comments & Whitespace Trimming

Internal template comments are stripped at the lexical analysis stage and never appear in the final rendered output. Whitespace modifiers strip surrounding spaces and line breaks.

template.html 
{# This comment is completely stripped during lexing: zero runtime cost #}

<div>
  <!-- Hyphen trims leading and trailing whitespace -->
  {{- user.name -}}
</div>

<!-- Trimming inside control tags -->
{%- for tag in tags -%}
  <span class="tag">{{ tag }}</span>
{%- end -%}

Conditionals (if / elif / else / end)

Control execution flow using multi-branch conditionals. Qalam fully supports Djazair's native end keyword as well as traditional endif.

template.html 
{% if user.role == "admin" %}
  <span class="badge badge-admin">Administrator</span>
{% elif user.role == "editor" %}
  <span class="badge badge-editor">Editor</span>
{% elif user.role == "moderator" %}
  <span class="badge badge-mod">Moderator</span>
{% else %}
  <span class="badge badge-guest">Standard Guest</span>
{% end %}
Djazair Truthiness Harmony: In condition evaluation, the following values are treated as false: False, Null, 0, empty string "", empty array [], and empty map {}.

Loops & Loop Metadata

Iterate over arrays and collections with {% for item in items %} ... {% end %}. Inside the loop, Qalam automatically injects rich metadata via the loop object.

Metadata Property Type Description Example Value
loop.index Number Current iteration count, starting at 1. 1, 2, 3...
loop.index0 Number Current 0-based iteration index. 0, 1, 2...
loop.first Boolean True on the first iteration of the loop. True / False
loop.last Boolean True on the final iteration of the loop. True / False
loop.length Number Total count of items in the iterated collection. 15
template.html 
<table>
  <tr><th>#</th><th>Product</th><th>Price</th></tr>
  {% for product in products %}
  <tr class="{% if loop.first %}first-row{% elif loop.last %}last-row{% end %}">
    <td>{{ loop.index }} of {{ loop.length }}</td>
    <td>{{ product.title | capitalize }}</td>
    <td>${{ product.price | round(2) }}</td>
  </tr>
  {% end %}
</table>

Template Inheritance (extends & block)

Define global layouts once and let individual pages inject content into named blocks. Unoverridden blocks in parent layouts retain their default markup.

views/layout.html 
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <title>{% block title %}Djazair Enterprise Portal{% end %}</title>
  {% block styles %}<link rel="stylesheet" href="/style.css" />{% end %}
</head>
<body>
  <header>
    {% block header %}<nav>Default Application Navigation</nav>{% end %}
  </header>

  <main class="main-content">
    {% block content %}{% end %}
  </main>

  <footer>
    {% block footer %}<p>&copy; 2026 Djazair Language Project</p>{% end %}
  </footer>
</body>
</html>
views/dashboard.html 
{% extends "layout" %}

{% block title %}Trading Dashboard • Djazair Portal{% end %}

{% block content %}
  <h1>Live Portfolios</h1>
  <p>Welcome back, {{ user.name }}!</p>
  <ul>
    {% for trade in trades %}
      <li>{{ trade.symbol }}: ${{ trade.value | round(2) }}</li>
    {% end %}
  </ul>
{% end %}

Direct Context Functions: fn(...)

Pass first-class Djazair functions directly inside the template data context. Qalam evaluates callables with parameters inline without requiring template macros or custom tags.

djazair 
use qalam

let tpl = `
<p>Greeting: {{ greet(user.name) }}</p>
<p>Total Amount: {{ calculateTax(order.subtotal, 0.19) }} DZD</p>
`

let output = qalam.renderString(tpl, {
    "user": {"name": "Riad"},
    "order": {"subtotal": 10000},
    "greet": fn(name) return "Marhaba, ${name}!" end,
    "calculateTax": fn(amount, rate) return amount * (1 + rate) end
})

print(output)

Filter Pipeline & Chaining

Pipe expressions sequentially through transformation filters using the pipe operator |. Arguments can be passed in parentheses.

template.html 
<!-- Multiple sequential pipes: trim whitespace, then capitalize -->
<h2>{{ "   algerian developer   " | trim | capitalize }}</h2>

<!-- Pipe with argument: join array with custom delimiter, then uppercase -->
<p>Tags: {{ post.tags | join(" • ") | upper }}</p>

<!-- Fallback default if value is null or empty -->
<p>Bio: {{ user.biography | default("No biography available.") }}</p>

Qalam includes over 20 standard transformations out of the box, fully compatible with Djazair language runtime semantics.

ltrim String None Strips leading whitespace. " hello" | ltrim → "hello"
rtrim String None Strips trailing whitespace. "hello " | rtrim → "hello"
replace String (old, new) Replaces occurrences of substring with replacement. "a-b-c" | replace("-", "/") → "a/b/c"

Registering Custom Filters

Extend Qalam with domain-specific formatting filters (currency symbols, relative timestamps, markdown parsers, status badges).

djazair 
use qalam

let v = new qalam.view({})

# Register custom Algerian Dinar currency filter
v.registerFilter("dzd", fn(val, args = [])
    return "${val} DZD"
end)

# Register custom HTML status badge filter
v.registerFilter("statusBadge", fn(status, args = [])
    if status == "paid"
        return "<span class='badge bg-success'>PAID</span>"
    elif status == "pending"
        return "<span class='badge bg-warning'>PENDING</span>"
    end
    return "<span class='badge bg-danger'>CANCELLED</span>"
end)

let html = v.renderString(
    "<p>Total: {{ amount | dzd }}</p><div>{{{ status | statusBadge }}}</div>",
    {"amount": 8500, "status": "paid"}
)

print(html)

Kasbah Web Framework Integration Recipe

Combine Qalam with Kasbah for full-stack, enterprise-grade web development in Djazair.

server.dz 
use kasbah
use qalam

let app = new kasbah.app({"port": 8080})

# Initialize Qalam View Engine with views/ folder and AST caching
let viewEngine = new qalam.view({
    "views": "views",
    "cache": True
})

# Route handler returning rendered HTML
app.get("/profile", fn(req, res)
    let renderedHtml = viewEngine.render("profile", {
        "title": "User Profile",
        "user": {"name": "Riad Harizi", "email": "riad@example.com"},
        "stats": {"orders": 14, "credits": 520.00}
    })
    
    res.status(200).html(renderedHtml)
end)

app.listen()

Security Architecture & Safeguards

Qalam is engineered from the ground up for high-risk web production environments with multi-layered defensive sandboxing.

Automatic XSS Sanitization
Auto-Escaped
All {{ ... }} expressions are automatically sanitized through escaper.escapeHtml() before output generation, preventing reflected, stored, and DOM-based Cross-Site Scripting.
Path Traversal Boundary Defense
Sandbox Enforced
TemplateLoader.getSafePath() resolves canonical paths and guarantees that all template identifiers (including layouts in {% extends %} and partials in {% include %}) strictly reside inside the configured views directory. Traversal sequences (../, ..\) and null bytes trigger fatal security exceptions.

In-Memory AST Compilation Caching

In high-concurrency production deployments, reading and parsing template files from disk on every HTTP request consumes excessive I/O and CPU cycles.

Qalam features an automatic In-Memory AST Compilation Cache:

  1. When v.render("page") is first called, the template file is read from disk, tokenized, and compiled into an AST tree.
  2. The parsed AST is stored in an in-memory dictionary.
  3. All subsequent requests for that template bypass the disk, lexer, and parser entirely, executing directly against the cached AST node tree with up to 30x faster response latency.
djazair 
# Production: Caching enabled (default)
let prodView = new qalam.view({"views": "views", "cache": True})

# Local Development: Disable cache to immediately see disk edits without restarting server
let devView = new qalam.view({"views": "views", "cache": False})

# Programmatic cache flush (e.g. after deploying new template updates)
prodView.clearCache()

view Class & Constructor

The main template orchestrator class exported by qalam.

new qalam.view(config = {}) → view
Constructor
Instantiates a new View template engine instance with configuration options.
OptionTypeDefaultDescription
"views" String "views" Base filesystem directory containing template files.
"cache" Boolean True Enables or disables in-memory compiled AST caching.

view Methods

Methods available on any instantiated view object.

v.render(templateName, data = {}) → String
Core Engine
Reads a template file by name identifier (e.g. "home" or "users/details"), resolves layout inheritance ({% extends %}), executes loops and conditionals, and returns the rendered HTML string.
v.renderString(templateString, data = {}, blocksMap = {}) → String
In-Memory
Directly compiles and renders an in-memory template text string with context variables, without touching the filesystem.
v.registerFilter(name, callback) → Void
Filter
Registers a custom transformation filter. The callback must accept (val, args = []) and return the transformed string or value.
v.getSafePath(templateName) → String
Security
Resolves and validates the absolute path for a template name, asserting that it does not escape the configured views boundary. Throws fatal error on traversal attempts.
v.readFile(templateName) → String
Filesystem
Reads and returns the raw UTF-8 string content of a validated template file from disk.
v.clearCache() → Void
Cache
Clears all compiled AST trees from memory cache, forcing templates to be re-read and re-parsed on their next invocation.
